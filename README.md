# projectskill

为 AI 协作项目保存记忆、核对进展、守住范围的轻量 Skill。当前版本：v3；Skill 名称：`project-docs`。

## 核心功能

- **把对话压缩成项目记忆**：保存用户偏好、决定、否决理由、待答问题和未完成工作，让新会话能够接手，不依赖原聊天记录。
- **让进展有依据**：记录验证版本、环境和证据，区分已验证与待复核。
- **保留自主判断**：AI 在授权范围内选择方法；目标、项目形态与预算的变化由用户决定。
- **让经验可复用**：用案例检验改进，保留历史，撤回过时规则，减少重复文档。

## 工作流程

1. **启用**：明确目标、范围和验收方式，建立项目入口。
2. **开工**：读取当前状态，核对证据和待办。
3. **执行**：自主完成授权工作，记录重要决定与纠正。
4. **收尾**：只在有新决定、证据或实质变更时更新记录。
5. **复查**：检查新会话能否接手，精简不再有效的规则。

## 项目中保存什么

| 文件 | 用途 |
|---|---|
| `PROJECT.md`（或已有的 `HANDOFF.md`） | 唯一当前状态：目标、偏好、进展、待办 |
| `LEARNINGS.md` | 经验与决定，包括否决理由和适用条件 |
| `RUN_LOG.md` | 按需查阅的历史证据 |

小型一次性任务可只使用状态文件。

## 使用

下载 [Skill 包](project-docs-v3.skill)，导入支持该格式的工具；也可将 [SKILL.md](SKILL.md) 放入所用 Agent 支持的 Skill 目录下的 `project-docs/` 文件夹。

在项目的 `AGENTS.md` 或 `CLAUDE.md` 中注明：

> 本项目按 project-docs 管理，状态文件是 PROJECT.md。

入口文件是否自动加载取决于所用工具；不支持时，在新会话中主动提供 Skill 和状态文件。

## 适用边界

这是纯文本协作协议，不附带程序，也不会自动持续运行或扩张项目。v3 尚未完成真实项目行为验证，以上为设计功能，实际效果取决于 Agent 的执行与项目实践。
